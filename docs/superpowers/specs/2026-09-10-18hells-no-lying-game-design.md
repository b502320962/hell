# 《十八层地狱：这里禁止说谎》游戏设计文档

- 日期：2026-09-10
- 状态：待用户审阅
- 形态：微信小程序（Taro 4 + React 18 + TypeScript）

## 1. 概述

根据小说《十八层地狱：这里禁止说谎》改编的剧情解谜闯关游戏。仅借用小说世界观设定（地狱、禁止说谎的规则），剧情、谜题、角色全部原创，规避版权风险。

- 类型：剧情解谜闯关
- 平台：微信小程序
- 内容规模：十八层地狱全量
- 核心机制：双向谎言博弈（玩家守规 + 识破 NPC 谎言）
- 美术：中式怪谈暗黑风

## 2. 世界观与结构

玩家生前是一个"永远在说谎的人"，死后坠入地狱。地狱新规：**这里禁止说谎**——说谎者受刑，说真话者获得通行资格。玩家逐层证明自己的"真"，在第十八层面对最终审判与身份反转（原创核心悬念）。

十八层按"谎言的类型"分组，每层有独立主题，不是重复爬塔：

| 分组 | 层数（传统刑罚名） | 主题 | 玩法侧重 |
|------|------|------|----------|
| 舌之狱 | 1-3 拔舌·剪舌·铁树 | 谎言从口出 | 教学+基础证词矛盾题 |
| 镜之狱 | 4-6 孽镜·蒸笼·铜柱 | 谎言照出原形 | 观察细节、镜中证据 |
| 刑之狱 | 7-9 刀山·冰山·油锅 | 谎言的代价 | 高风险选择、资源管理 |
| 冤之狱 | 10-12 牛坑·石压·舂臼 | 冤案与错判 | 审判定罪（罪人可能是冤的） |
| 忏之狱 | 13-15 血池·枉死·磔刑 | 忏悔与宽恕 | 情感抉择、多分支剧情 |
| 审之狱 | 16-18 火山·石磨·刀锯 | 终极审判 | 全机制综合+剧情反转+多结局 |

- 每层标配流程：入场剧情 → 主谜题（1-2 个）→ 判官对质 → 通行判定
- 单层时长 10-15 分钟，全通关约 3-4 小时
- 贯穿配角：引路鬼差、说谎的同伴、各层判官；第 18 层回收伏笔

## 3. 核心机制：双向谎言博弈

### 3.1 玩家侧：守规

- 状态「舌」：初始 3 条，等于 3 点生命
- 对话选项混有真话/谎话，玩家自行判断；选谎话 → 判官识破 → 拔舌一条，剧情走受刑支线（受刑有剧情，非纯惩罚）
- 3 条舌耗尽 → 该层失败从层首重来（谜题进度保留）
- 特殊关卡：部分层的通关条件是"必须说一次谎"（如替冤魂隐瞒真相）。此时说谎不扣舌，但产生「谎言债务」，在后续某层结算

### 3.2 NPC 侧：破谎

- 证词/物证存入「因果簿」，玩家随时翻阅比对
- 矛盾点类型：证词互斥、证词与物证冲突、NPC 前后陈述不一
- 对质：从因果簿选矛盾证据呈给判官；选对 → NPC 现形；选错 → 扣一条舌（妄言）
- 每层 2-4 个矛盾点，后期有干扰项与多证词纠缠

### 3.3 资源：真言香火

- 通关获得香火，用于：层内提示（查询线索解读，价格递增）、死亡续命（保舌复活）
- 纯单机，无内购

### 3.4 结局

由 舌剩余数、谎言债务数、关键分支选择 三个变量决定，至少 4 结局：诚实善终 / 带债转世 / 拔舌永狱 / 第十八层真相反转专属结局。

## 4. 引擎架构（数据驱动）

技术栈：Taro 4 + React 18 + TypeScript；状态管理 Zustand；构建目标微信小程序。

```
src/
├── engine/                 # 剧情谜题引擎（不含具体剧情）
│   ├── GameState.ts        # 全局状态：舌、香火、因果簿、谎言债务、层进度
│   ├── Interpreter.ts      # 剧本解释器：消费节点流，驱动对话/选项/跳转
│   ├── RuleEngine.ts       # 谎言判定、对质判定、惩罚结算
│   ├── SaveManager.ts      # 存档（微信 storage，云端预留）
│   └── conditions.ts       # 条件表达式求值（分支/结局判定）
├── data/levels/            # level01.json ... level18.json + schema.ts
├── components/             # 对话气泡、选项列表、因果簿、状态栏等通用 UI
├── pages/                  # 首页 / 图鉴 / 层内游戏页 / 结算页 / 结局页
└── assets/                 # 插图、音效（按层分包）
```

### 4.1 剧本 JSON 格式

所有层的所有表现归结为节点类型，由引擎顺序执行：

```jsonc
{
  "id": "level01",
  "title": "拔舌狱",
  "nodes": [
    { "type": "dialogue", "speaker": "鬼差", "text": "……", "next": "c1" },
    { "type": "choice", "prompt": "鬼差问你生前可曾说过谎",
      "options": [
        { "text": "说过，但都是善意的谎言", "isLie": true, "penalty": "tongue", "next": "punish_1" },
        { "text": "说过很多，我来认罪", "isLie": false, "reward": { "incense": 2 }, "next": "c2" }
      ]},
    { "type": "clue", "add": "clue_testimony_1", "text": "获得证词：……" },
    { "type": "puzzle", "puzzleType": "contradiction" },
    { "type": "branch", "cond": "tongue >= 2 && debt == 0", "then": "good_end", "else": "next" }
  ]
}
```

节点类型：`dialogue`（对话）、`choice`（选项）、`clue`（获得证词/物证）、`puzzle`（谜题）、`branch`（条件分支）、`ending`（层结局）。谜题节点内部可再嵌套子流程。

### 4.2 五种可复用谜题模板

1. **矛盾指认**：多条证词中点击选出与物证冲突的一条
2. **真话独木桥**：一组选项只有全选真话才安全，混入说谎项
3. **镜中找异**：两张场景图找不同/找异常（镜子照出谎言原形）
4. **审判定罪**：从因果簿选证据链定罪，选错有后果
5. **谎言代价**：说谎换眼前利益但积累债务（资源管理抉择）

### 4.3 判定规则（RuleEngine）

- `isLie` 判定结合上下文条件：玩家**已知真相而否认**才算谎；引擎用条件表达式判断，避免死板
- 对质选错证据 = 妄言扣舌；同一矛盾点错两次自动给提示
- 结局 = `f(tongue, debt, keyBranches)` 一次性求值

### 4.4 开发顺序

1. 引擎 + 第 1 层跑通全流程（含真机验证）
2. 批量铺 2-18 层内容（JSON + 插图）
3. 每完成一组（3 层）做一次真机测试
4. 全量整合 + 分包联调 + 提审

## 5. UI 与美术

### 5.1 页面流程（全局 5 页面）

```
首页（阴阳封面：进入地狱 / 继续进度）
 ├→ 图鉴页：十八层"纵深向下的塔"，已通关层亮起可重玩/看收集度，
 │   未解锁层为雾中坊门
 └→ 层内游戏页（一个页面承载所有层，由引擎驱动）
      ├ 顶部极简状态栏一行：舌 ×3 ｜ 香火 ×N ｜ 因果簿入口
      ├ 主舞台：层插图 + 对话气泡
      ├ 对话气泡：深色半透明(0.92)、圆角(14px)、文字左对齐、无滚动条，
      │   长文本分段点击翻页，完整显示
      ├ 选项列表：说谎选项无视觉标记，玩家自行判断，选后结算时揭示
      └ 因果簿抽屉：点击滑出，证词/物证卡片，支持长按比对
 ├→ 结算页：层通关评语 + 香火结算
 └→ 结局页：多结局演出 + 图鉴解锁
```

### 5.2 美术规范

- 配色：墨黑底 `#0d0d10` + 朱砂红 `#b03a2e` + 青铜金 `#c9a227`
- 插图：AI 生成国风线描/剪影风格，每层 1 主场景 + 2-3 关键物件图；标题用书法体
- 文字描边+阴影保证深底可读；动画仅淡入淡出与血色渐变
- 音频：层内循环低鸣环境音 + 拔舌/对质命中音效；BGM 用免费商用曲库

## 6. 分包与存档

- 微信限制：主包 2MB、总包 30MB，必须分包
  - 主包：引擎 + 通用组件 + 首页/图鉴 + 层 1-3（首启即玩）
  - subA：层 4-9；subB：层 10-15；subC：层 16-18 + 结局
  - 图鉴点击未加载分包时异步加载，加载中显示"雾气散去中…"
- 插图压缩为 WebP，每层资源 ≤1.5MB
- 存档：微信 `setStorage`，每层通关/重大选择触发自动保存；预留云开发同步接口（首版不做）

## 7. 错误处理与测试

- 剧本 JSON 加载失败/字段缺失：引擎抛出带层号+节点 ID 的明确错误，开发期在控制台可见，线上静默回退到层首并提供"重进此层"
- 存档损坏：校验版本号，损坏则备份旧档并新开档，弹窗告知
- 测试：引擎层用 Vitest 单测（节点流转、判定规则、结局求值）；每层 JSON 用 schema 校验脚本；真机测试覆盖每分组抽查 + 分包加载路径
